4. Learning Science Review

Recall: attempt a question before revealing the guide, compare and correct it. Delayed retrieval plus feedback follows The Learning Scientists’ practical guidance. The interface encourages this behavior; it cannot prove that a learner did not peek.

Spacing: first saved attempts become due the next day. Self-ratings use 1, 3, 7, 14, 30 and 60-day intervals; “Again” resets to one day. Same-day repeated ratings do not inflate intervals. Calendar arithmetic uses local dates. This is an explicit heuristic, not FSRS or a calibrated forgetting model.

Transfer: demonstrations require an explanation and artifact evidence. Capstones carry document IDs, test fixtures and checkpoints forward. Listening and page views never auto-complete skills. Existing knowledge can be demonstrated without repeating all introductory material.

Motivation: logged actual study drives streaks and seven-day activity. Missing a day preserves evidence. Avoid inflated XP, leaderboard pressure and passive time counters.

Retention scoring: a retention percentage is deliberately not invented. Quiz sample scores, due dates and recall ratings are inspectable signals. A defensible retention model would require delayed unseen assessments and sufficient history.

5. UX/UI Review

Today answers “where am I?” through the chosen goal; “what have I completed?” through demonstrations and the matrix; “what next?” through the prominent next action and its rationale; “what skills?” through evidence; and “what can I build?” through prerequisite-ready capstones.

The implementation uses local fonts, labelled forms, visible focus styles and accessible primary controls. At phone widths panels stack and navigation scrolls. The dependency graph scrolls within its own region and has equivalent text links. Browser narration supports speed and paragraph bookmarks; downloaded WAVs are better suited to background phone playback.

The persistent player occupies substantial mobile space; a future compact mode would help. Responsive browser checks are not physical Android acceptance or formal WCAG certification. Keyboard and label checks do not replace a full screen-reader audit.

7. Learning Graph Redesign

The graph is structured data in content/learning-graph.json. Prerequisites, arrows, ready topics and next links derive from the same records. Tests reject duplicate/missing IDs and cycles. Every node includes hours, difficulty, outcome, a recall question with feedback, a project task and a reference. Estimates are rough study hours, not completion promises.

Application route:
Python → documents → tokenization → local LLM
  → evaluation + safety → RAG → reproducible tools → agents
Optional extensions: embeddings → hybrid retrieval; quantization → device delivery.

Model route:
Python → probability/statistics + algebra/calculus
  → supervised learning → neural networks → PyTorch
Embeddings → self-attention → multi-head attention
Position information + neural nets + attention → transformer
Training workflow + transformer + data splits → tiny-model pretraining
Pretrained weights + evaluation → fine-tuning / LoRA

These are recommended pedagogical dependencies with AND semantics, not universal laws. TensorFlow is an alternative framework branch. Word2Vec is optional history. Using embeddings differs from training them. Fine-tuning uses existing pretrained weights and does not require finishing your own pretraining experiment.

The corrected explanations distinguish attention architecture, FlashAttention’s memory-access optimization, and KV reuse during inference. RoPE’s positional contribution depends on relative offsets while scores still depend on content (RoFormer). Recall@k now uses the fraction of relevant items retrieved, not simply whether any hit exists.

12. 30-Day Improvement Roadmap

  1. Days 1–7: three 20-minute sessions, one artifact, a five-question baseline and one Android audio transfer. Demonstrate existing Python skills if appropriate.
  2. Days 8–14: tokenization, local-model use, evaluation and safety. Write ten answerable and five unanswerable questions with expected sources. Benchmark one local model only if hardware fits.
  3. Days 15–21: complete the retrieval capstone using stable document IDs. Compare before/after changes against the same fixtures. Review due topics before adding new ones.
  4. Days 22–30: audit difficult quiz items, consolidate exports and validate offline phone use. Add embeddings only if they address observed retrieval misses.

This is a sustainable routine, not a promise to finish the entire curriculum in 30 days. No calendar reminders or unattended jobs were scheduled.

15. Example User Journeys

  1. Busy beginner: choose ten minutes, read one idea, attempt a small task and save partial evidence. Tomorrow offers recall and continuation without pretending that reading established mastery.
  2. Experienced developer: open a topic directly, explain it and attach an existing tested artifact. Mark a self-assessed demonstration; the planner moves onward without forced replay.
  3. Commute learner: prepare downloaded audio while parked, listen without screen interaction, explain it after parking, then build and log work on the laptop.
  4. Quiz learner: choose a topic or mixed sample, answer from memory and inspect explanations. Follow a missed-topic link. Even 100% on a small sample does not auto-complete a topic.
  5. Returning builder: search saved evidence for the earlier document loader, reuse its IDs and fixtures in the assistant capstone, then export before changing devices.
